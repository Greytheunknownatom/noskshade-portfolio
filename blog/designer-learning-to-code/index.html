Design x code

I’m a designer learning to code. Week one humbled me in a way I didn’t expect.

I thought the hard part would be the syntax. It was realising how many of my designs were missing half their screens.

Philip Nosike · 21 October 2026 · 5 min read

I’ve “started learning to code” more times than I’d like to admit.

A bit of C years ago. Some terminal commands. Tutorials I finished without really understanding.

This time I made one rule: only build things I designed myself. If I write a line of code, I should know exactly why it’s there.

The first thing code taught me had nothing to do with code

In Figma, a screen is a picture. In code, a screen is the result of some information: who the user is, what they’ve done, what’s still loading.

const screen = !user ? "loading" : user.posts.length ? "feed" : "empty";

// three screens. I had designed one.

That one line showed me two screens I had never drawn. The waiting one, and the empty one.

Learning to code didn’t make me less of a designer. It showed me which parts of my designs were just wishful thinking.

What I do differently now

  • Design the loading, empty and error screens next to the main one, not later.
  • Name layers the way a developer would name things.
  • Put rough work on a live link early, even when it’s embarrassing.

If you’re a designer thinking about learning to code: start with something you already designed. It hits differently.
